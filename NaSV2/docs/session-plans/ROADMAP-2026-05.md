- **Why:** AUDIT A4 + A5 + Risk #1 — three xtask hygiene gates

  stubs that return 0 inside CI. ENTITY §18.1–§18.4 require them as

  exit non-zero on a synthetic violation; CI workflow passes only when

  on G4 — no handlers yet).
- **Estimated days:** 3 (W1 D1–D3)
- **Touches:** xtask non-spine only.

### G2 — Bootstrap the domain core (`nas2-common` + `nas2-domain`)

- **Why:** AUDIT A1 + Risk #10 — both crates are 1-LOC stubs; every
  downstream layer is blocked on them. ENTITY §15 (multi-tenancy
  newtype), §20 (thiserror domain enums), §21 (repo layout) all hinge
  on these.
- **Success criterion:** `nas2-common` exports `TenantId`, `SiteId`,
  `UserId`, `RequestId`, `AppError`, `Page<T>` with serde + garde where
  appropriate; `nas2-domain` exports `Site`, `Post`, `User`, `Role`,
  `Capability`, `Block` enum (typed, exhaustive) with unit tests
  covering invariants; `cargo xtask architecture-check` stays green
  (no forbidden deps in domain).
- **Estimated days:** 5 (W1 D4–D5 + W2 D1–D3)
- **Touches:** non-spine. New `crates/<X>/Cargo.toml` may add `garde`
  features; workspace `Cargo.toml` UNCHANGED.

### G3 — Application ports + tenant middleware

- **Why:** AUDIT A1 (application 38 LOC, only Queue trait) + Risk #6
  (no `TenantContext`). ENTITY §2 hex layer 2; §15 says no function
  touching tenant-scoped data compiles without `&TenantContext`.
- **Success criterion:** `nas2-application::ports` includes
  `PostRepository`, `UserRepository`, `SiteRepository`, `MediaRepository`
  with `async-trait`; first use case `GetPublishedPageBySlug` lands in
  `application::queries`; `nas2-tenant::TenantContext` + middleware that
  populates `request.extensions()` and refuses missing headers; unit
  tests with `mockall`.
- **Estimated days:** 5 (W2 D4–D5 + W3 D1–D3)
- **Touches:** non-spine.

### G4 — First real `nas2-presentation` handler + capability gate

- **Why:** AUDIT A1 (presentation stub) + Risk #4. Without one real
  handler, the capability-coverage gate (G5/W4) has nothing to verify.
  ENTITY §14 demands `caps.require(...)` on every state-changing handler.
- **Success criterion:** `GET /api/v1/pages/:slug` handler reads via
  `GetPublishedPageBySlug`, requires `cms.page.read`, returns 404 vs
  401 vs 200 correctly; AppState wires `PostRepository` impl
  (in-memory test double + sqlx repo skeleton); axum integration test
  via `oneshot()` covers the three response codes; capability hash is
  computed and exposed via a helper used later by cache key composition.
- **Estimated days:** 4 (W3 D4–D5 + W4 D1–D2)
- **Touches:** non-spine. May need to wire `PostRepository` impl in
  `nas2-infrastructure::persistence` (new module).

### G5 — Real `capability-coverage` gate + planning trail backfill + first perf baseline

- **Why:** Closes Risk #3 (orphan RFC/ADR), Risk #2 (no perf baseline),
  Risk #1 fully (last stub gate becomes real once G4 produces handlers).
- **Success criterion:**
  - `xtask capability-coverage` rejects a handler without
    `caps.require(...)` (synthetic test commit)
  - `RFC-001`, `RFC-003` (TaskSupervisor), `RFC-004` (pgmq), `ADR-001`,

- **Estimated days:** 3 (W4 D3–D5; D5 includes RETRO)
