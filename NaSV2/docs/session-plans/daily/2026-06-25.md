P1 · `migrations/0004_users.sql` (NEW)

```sql
-- 0004_users.sql · ENTITY §15 · ADR-010 shape (RLS in 0007).

CREATE TABLE IF NOT EXISTS users (
    id              UUID PRIMARY KEY,
    tenant_id       UUID NOT NULL,
    email           CITEXT NOT NULL,
    password_hash   TEXT NOT NULL,         -- argon2id encoded
    display_name    TEXT,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE EXTENSION IF NOT EXISTS citext;

CREATE UNIQUE INDEX IF NOT EXISTS users_tenant_email_idx
    ON users (tenant_id, email);

CREATE TRIGGER users_set_updated_at_trg
    BEFORE UPDATE ON users
    FOR EACH ROW EXECUTE FUNCTION posts_set_updated_at();
    -- reuses the trigger function from 0002
```

  *Engineering note:* `CITEXT` is the case-insensitive text type
  (case folding done by PG); RFC-5321 envelope emails are case-
  sensitive in local-part but most providers ignore case anyway.
  Storing as CITEXT means `find_by_email("Foo@Bar.com")` matches a
  row stored as `foo@bar.com` — the UX expectation.

P2 · `migrations/0005_roles_caps.sql` (NEW)

```sql
-- 0005_roles_caps.sql · ENTITY §14 · ADR-010 shape.

CREATE TABLE IF NOT EXISTS roles (
    id           UUID PRIMARY KEY,
    tenant_id    UUID NOT NULL,
    name         TEXT NOT NULL,
    description  TEXT,
    created_at   TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX IF NOT EXISTS roles_tenant_name_idx
    ON roles (tenant_id, name);

-- A role has a set of capability NAMES (matching nas2_domain::
-- capability::Capability::as_str()). Storing strings rather than a
-- FK to a `capabilities` table — capabilities are typed enum in
-- code; the DB just records the names.
CREATE TABLE IF NOT EXISTS role_capabilities (
    role_id      UUID NOT NULL REFERENCES roles(id) ON DELETE CASCADE,
    tenant_id    UUID NOT NULL,
    capability   TEXT NOT NULL
                 CHECK (capability ~ '^[a-z][a-z0-9._]*[a-z0-9]$'),
    PRIMARY KEY (role_id, capability)
);

CREATE INDEX IF NOT EXISTS role_capabilities_tenant_idx
    ON role_capabilities (tenant_id);
```

COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **`CREATE EXTENSION IF NOT EXISTS citext`** requires the extension
     to be available — postgres ships it as a contrib. testcontainers
     postgres image includes it.
  2. **Capability name regex `^[a-z][a-z0-9._]*[a-z0-9]$`** — must
     start with letter, end with letter/digit; allows dots and
     underscores in middle. Matches `cms.page.read` shape.
  3. **`ON DELETE CASCADE` on role_id and user_id**: if a role is
     dropped, every assignment vanishes. Acceptable. If you want
     soft-delete semantics, that's a Post-1 ADR.
  4. **`citext` columns in `find_by_email` queries** — sqlx binding
     uses regular `String`; PG handles the case-fold. No special
     handling in Rust.
  5. **5 migrations applied in one go** — `sqlx::migrate::Migrator`
     applies them transactionally per migration. If 0007 fails, 0004-
     0006 are still applied (a forward-only commit). Recovery: rerun
     the rollback then `db migrate` again.

PRE-RESOLVED DEFAULTS
═════════════════════════════════════════════════════════════════════

  • CITEXT for email — covers 99% of use; if production wants
    case-sensitive local-parts (compliance), switch to TEXT + lower()
    in the index and live with lowercase normalisation.
  • Capability stored as TEXT (not enum) — schema agility wins over
    FK referential integrity.
  • Cascading deletes for role / user → assignments. Soft-delete
    is a separate concern.
