P2 · `crates/presentation/src/csrf.rs` (NEW)

  Pattern: double-submit cookie. On any state-changing request, the
  client MUST send `X-CSRF-Token` header that equals the value of
  the `ax_csrf` cookie. The cookie is set by `login` (and refreshed
  on subsequent state-changing requests) with random 32-byte value.

```rust
//! Double-submit CSRF protection.
//!
//! Idea: an attacker can force a victim's browser to submit a
//! cross-origin request WITH the victim's cookies, but CANNOT read
//! a victim's cookies (Same-Origin Policy). If the cookie's value
//! must be mirrored in a header (which the attacker also can't read),
//! the attack fails.
//!
//! Cookie is set HttpOnly=FALSE so JS can read it (client mirrors it
//! into the header). SameSite=Strict adds defence-in-depth.

use axum::{
    extract::Request,
    http::{header, Method, StatusCode},
    middleware::Next,
    response::Response,
};
use nas2_common::AppError;

const CSRF_COOKIE: &str = "ax_csrf";
const CSRF_HEADER: &str = "x-csrf-token";

pub async fn csrf_middleware(
    req: Request,
    next: Next,
) -> Result<Response, AppError> {
    let is_state_change = matches!(*req.method(),
        Method::POST | Method::PATCH | Method::PUT | Method::DELETE);
    if !is_state_change {
        return Ok(next.run(req).await);
    }
    let cookie_val = extract_csrf_cookie(&req);
    let header_val = req.headers().get(CSRF_HEADER).and_then(|v| v.to_str().ok());
    match (cookie_val, header_val) {
        (Some(c), Some(h)) if c == h => Ok(next.run(req).await),
        _ => Err(AppError::Forbidden("csrf_mismatch".into())),
    }
}

fn extract_csrf_cookie(req: &Request) -> Option<String> {
    let cookie = req.headers().get(header::COOKIE)?.to_str().ok()?;
    for pair in cookie.split(';') {
        if let Some((k, v)) = pair.trim().split_once('=') {
            if k == CSRF_COOKIE {
                return Some(v.to_owned());
            }
        }
    }
    None
}
```

  Add `pub mod csrf;` to lib.rs. Wire onto the protected sub-router
  (BEFORE JWT middleware — runs first request-side, so cookie+header
  match before any business work):

  ```rust

  use base64::Engine;
  pub fn generate_token() -> String {
      let mut bytes = [0u8; 32];
      rand::Rng::fill(&mut rand::rngs::OsRng, &mut bytes);
      base64::engine::general_purpose::URL_SAFE_NO_PAD.encode(bytes)
  }
  ```

    handlers don't process invalid-CSRF requests at all.

    reviewer doesn't "fix" this.
