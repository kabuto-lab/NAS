P1 · Implement `list_published` in `post.rs`

```rust
async fn list_published(
    &self,
    tenant: TenantId,
    site: SiteId,
    page: u32,
    per_page: u32,
) -> Result<Page<Post>, AppError> {
    // Validate / clamp pagination params.
    if per_page == 0 {
        return Err(AppError::Validation("per_page must be >= 1".into()));
    }
    let per_page = per_page.min(100);     // hard ceiling
    let page = page.max(1);
    let offset = (u64::from(page - 1)) * u64::from(per_page);

    let site_uuid = site.into_uuid();
    with_tenant(&self.pool, tenant, |tx| async move {
        // Single SQL with COUNT window: returns rows + total for "free".
        let rows: Vec<(PostRow, i64)> = sqlx::query_as::<_, (PostRow, i64)>(
            "SELECT id, site_id, tenant_id, slug, title, status, \
                    published_at, blocks, custom_type, \
                    COUNT(*) OVER() AS total \
             FROM posts \
             WHERE site_id = $1 AND status = 'published' \
             ORDER BY published_at DESC, id \
             LIMIT $2 OFFSET $3"
        )
            .bind(site_uuid)
            .bind(i64::from(per_page))
            .bind(i64::try_from(offset)
                  .map_err(|_| AppError::Validation("offset overflow".into()))?)
            .fetch_all(&mut **tx).await
            .map_err(|e| { tracing::error!(error=%e, "list_published"); AppError::Internal })?;

        let total: u64 = rows.first().map(|(_, t)| u64::try_from(*t).unwrap_or(0)).unwrap_or(0);
        let items: Result<Vec<_>, _> = rows.into_iter()
            .map(|(r, _)| r.into_domain()).collect();
        Ok(Page::new(items?, total, page, per_page))
    }).await
}
```

  The compound `(PostRow, i64)` tuple form requires sqlx 0.8+ —
  workspace has it.

  Alternative if the tuple form is awkward: add a `PostRowWithTotal`

async fn list_published_returns_only_published_in_published_at_order() {
    let (_pg, repo, pool) = seed_pool_and_repo().await;
    let tenant = TenantId::new_v4();
    let site = SiteId::new_v4();
    // Seed 3 published + 1 draft posts
    for i in 0..3 {
        seed_post(&pool, tenant, site, &format!("p{i}"), "published").await;
        tokio::time::sleep(std::time::Duration::from_millis(10)).await; // diff timestamps
    }
    seed_post(&pool, tenant, site, "draft1", "draft").await;

    let page = repo.list_published(tenant, site, 1, 10).await.unwrap();
    assert_eq!(page.items.len(), 3, "drafts must be filtered out");
    assert_eq!(page.total, 3);
    // Newest first
    assert_eq!(page.items[0].slug.as_str(), "p2");
    assert_eq!(page.items[2].slug.as_str(), "p0");
}

#[tokio::test]
#[ignore = "needs Docker"]
async fn list_published_paginates_correctly() {
    let (_pg, repo, pool) = seed_pool_and_repo().await;
    let tenant = TenantId::new_v4();
    let site = SiteId::new_v4();
    for i in 0..7 {

═════════════════════════════════════════════════════════════════════
COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **`COUNT(*) OVER()` returns the same total for every row.**
     The window has no PARTITION, so each row carries the same count.
     Cheap (one logical pass).
  2. **`OFFSET` on large datasets is slow.** Per-page ≤ 100 limits
     this. For deep pagination (page > 100), introduce cursor
     pagination in a later month — ADR-required.
  3. **`ORDER BY published_at DESC, id`** — id tiebreaks identical
     timestamps. Without the tiebreaker, pagination can skip or
     duplicate rows under concurrent inserts.
  4. **`i64::try_from(u64)`** can fail at u64::MAX/2 — `offset` is
     bounded by `page * per_page`, capped at u32::MAX * 100 ≈ 4 ×
     10¹¹. Mapped to Validation error.
  5. **Bench placeholder** must compile but not fail; eventually
     the operator wires a real fixture. Add the bench filename to a
     follow-up checklist (M2 W6 D5).
