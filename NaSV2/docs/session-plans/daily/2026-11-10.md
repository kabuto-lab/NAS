P1 · `docs/adr/ADR-019-leptos-island-state-pattern.md` (NEW)

  ~150 LOC, structured:
  - Status: Accepted · 2026-11-10
  - Context: M7 introduces 5+ Leptos islands. Cross-island state
    (current user, caps, csrf, tenant) and per-island state need a
    consistent pattern.
  - Decision: **signal-based per-island reactivity** +
    **`provide_context` for admin-shell-wide state**. Reject
    alternatives:
    - Single global RwSignal → SSR snapshot pollution
    - leptos_router state → URL-only, can't carry rich types
    - Server-only state passed as props → re-render every
      navigation, no client-side reactivity
  - Implementation patterns:
    ```rust
    // 1. Shell-level: provide_context once at AdminLayout root
    #[component]
    pub fn AdminLayout(children: Children) -> impl IntoView {
        let admin_ctx = AdminContext {
            user: ...,
            caps: CapabilitySet::from_iter(...),
            csrf: ...,
            tenant: ...,
        };
        provide_context(admin_ctx);
        view! { <div class="admin"><nav>...</nav>{children()}</div> }
    }

    // 2. Per-island: use_context + create_signal
    #[component]
    pub fn PostList() -> impl IntoView {
        let ctx = use_context::<AdminContext>().expect("AdminContext");
        let (filter, set_filter) = create_signal(Filter::default());
        // ...
    }
    ```
  - TLA layers: L1 type-safe context, L2 zero per-render alloc beyond
    signal subscriptions, L3 islands are isolated render units,
    L4 hydration mismatch detection via Leptos's strict mode.
  - Consequences: + ergonomic, type-safe, SSR-friendly. − requires
    every island to `.expect("AdminContext")` (use `expect_context()`
    leptos helper).
  - References: ENTITY §3.2 (frontend), M7-VISION-AND-ARCHITECTURE
    §3.2.

P2 · `crates/presentation/src/admin/context.rs` (NEW)

```rust
//! Admin-shell context provided once at the layout root and
//! consumed by every island. ADR-019.

use nas2_common::{TenantId, UserId};
use nas2_domain::{Capability, CapabilitySet};

#[derive(Clone, Debug)]
pub struct AdminContext {
    pub user_id: UserId,
    pub user_email: String,
    pub tenant_id: TenantId,
    pub caps: CapabilitySet,
    pub csrf_token: String,
    /// Set by the server before SSR; islands read it once.
    pub api_base: String,
}

impl AdminContext {
    /// Helper used by nav rendering + per-island guards.
    #[must_use]
    pub fn has(&self, cap: Capability) -> bool { self.caps.contains(cap) }
}
```

P3 · `crates/presentation/src/admin/nav.rs` (NEW — Leptos component)

```rust
//! Capability-aware admin navigation · ADR-019 consumer.

use leptos::prelude::*;
use leptos_router::components::A;
use nas2_domain::Capability;

use crate::admin::context::AdminContext;

#[component]
pub fn AdminNav() -> impl IntoView {
    let ctx = expect_context::<AdminContext>();
    let email = ctx.user_email.clone();

    view! {
        <aside class="admin-nav" aria-label="admin navigation">
            <header class="admin-nav-header">
                <span class="brand">AX•CMS</span>
                <span class="user-email">{email}</span>
            </header>
            <ul role="menu">
                <NavItem href="/admin"        label="Dashboard"  cap=None/>
                <NavItem href="/admin/posts"  label="Posts"      cap=Some(Capability::CmsPageRead)/>
                <NavItem href="/admin/media"  label="Media"      cap=Some(Capability::MediaUpload)/>
                <NavItem href="/admin/comments" label="Comments" cap=Some(Capability::CommentsModerate)/>
                <NavItem href="/admin/users"  label="Users"      cap=Some(Capability::ManageUsers)/>
                <NavItem href="/admin/themes" label="Themes"     cap=Some(Capability::ManageSite)/>
                <NavItem href="/admin/plugins" label="Plugins"   cap=Some(Capability::ManageSite)/>
            </ul>
            <footer>
                <form method="post" action="/admin/logout">
                    <input type="hidden" name="csrf" value=ctx.csrf_token.clone()/>
                    <button type="submit" class="link-button">Logout</button>
                </form>
            </footer>
        </aside>
    }
}

#[component]
fn NavItem(href: &'static str, label: &'static str, cap: Option<Capability>) -> impl IntoView {
    let ctx = expect_context::<AdminContext>();
    let visible = move || cap.is_none_or(|c| ctx.has(c));
    view! {
        <Show when=visible fallback=|| ()>
            <li role="menuitem">
                <A href=href>{label}</A>
            </li>
        </Show>
    }
}
```

`is_none_or` is Rust 1.82+; toolchain pin (1.85) covers it.

PERFORMANCE / SECURITY CONSIDERATIONS
═════════════════════════════════════════════════════════════════════

  - Nav HTML is rendered server-side every request — no caching yet
    (M10 wires page cache). Cost: O(7 cap-checks) per request,
    negligible.
  - CSRF token injected into the logout form via context — never
    appears in cleartext logs (context is per-request, dropped after
    response).
  - `expect_context::<AdminContext>()` panics if missing; that's
    intentional — a panic at SSR time bubbles to a 500. Tests cover
    the happy path. The router guarantees `AdminLayout` wraps every
    admin response.
  - SSR hydration mismatch is a runtime cost — Leptos detects in dev.
    Strict pattern: islands read initial state from context (SSR-
    populated), never from `fetch()` on mount.

═════════════════════════════════════════════════════════════════════
COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **`leptos::ssr::render_to_string` is sync** in 0.7. Awaiting
     inside `view!` won't work; load data BEFORE the view (server
     function or handler).
  2. **`expect_context` panics if context missing** → leak between
     islands rendered outside `AdminLayout`. Add a debug assertion
     at handler-level: every admin handler renders via `AdminLayout`,
     not raw view.
  3. **`tower_http::services::ServeDir`** requires `tower-http` feature
     `fs` — already in workspace deps (verify with `grep tower-http
     Cargo.toml`).
  4. **CSS path** `/admin/static/admin.css` must be served BEFORE the
     `RequireCaps` extractor (CSS is public). Mount the `ServeDir`
     OUTSIDE the admin router's nesting, OR allow `static/*` in the
     extractor.
  5. **Logout form uses POST + CSRF** (not GET) — prevents
     cross-site logout via image-tag attack. The action handler
     `/admin/logout` lands W1 D4.
