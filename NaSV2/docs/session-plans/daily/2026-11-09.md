```rust
//! Admin route capability gate · M7 W1 D1.
//!
//! Defence-in-depth: M2 use cases already check `caps.contains()`.
//! This extractor ensures the request short-circuits BEFORE the
//! handler runs, with two response shapes:
//!   - browser (Accept: text/html) → 302 redirect to login OR HTML 403
//!   - API client (Accept: application/json) → 401/403 JSON
//!
//! ## Architecture
//!
//! The extractor consumes `Extension<CapabilitySet>` (injected by
//! `jwt_middleware`, M2 W7 D2) plus the request `HeaderMap` to
//! sniff `Accept`. It returns `()` on success or short-circuits
//! with `Response`.
//!
//! ## TLA layers
//!
//! - L1 Correctness: capability comparison uses `Capability` enum
//!   (compile-time), NOT string compare.
//! - L2 Performance: BTreeSet::contains is O(log n); n ≤ 6 today.
//! - L3 Scalability: extractor is stateless; no allocations.
//! - L4 Operability: emits `tracing::warn!` on cap-fail with
//!   `tenant_id`, `user_id`, `required_cap`, `accept_header`.

use std::marker::PhantomData;

use axum::{
    extract::FromRequestParts,
    http::{header, request::Parts, StatusCode, Uri},
    response::{IntoResponse, Redirect, Response},
};
use nas2_common::{AppError, UserId};
use nas2_domain::{Capability, CapabilitySet};
use nas2_tenant::TenantContext;

/// Type-level capability requirement. Use like:
/// ```ignore
/// async fn list_posts(_: RequireCaps<CmsPageRead>, ...) -> ... { }
/// ```
pub struct RequireCaps<C: CapabilityMarker>(PhantomData<C>);

/// Trait that materialises a capability at the type level.
pub trait CapabilityMarker: Send + Sync + 'static {
    const CAP: Capability;
}

/// Empty marker macro for terse declarations.
#[macro_export]
macro_rules! require_caps {
    ($name:ident, $variant:ident) => {
        pub struct $name;
        impl $crate::admin::guard::CapabilityMarker for $name {
            const CAP: nas2_domain::Capability = nas2_domain::Capability::$variant;
        }
    };
}

// Declared once per capability for ergonomic handler signatures.
require_caps!(CmsPageRead,     CmsPageRead);
require_caps!(CmsPageDraft,    CmsPageDraft);
require_caps!(CmsPagePublish,  CmsPagePublish);
require_caps!(MediaUpload,     MediaUpload);
require_caps!(ManageUsers,     ManageUsers);
require_caps!(ManageSite,      ManageSite);
require_caps!(CommentsModerate, CommentsModerate);

impl<C: CapabilityMarker, S> FromRequestParts<S> for RequireCaps<C>
where
    S: Send + Sync,
{
    type Rejection = Response;

    async fn from_request_parts(parts: &mut Parts, _state: &S) -> Result<Self, Self::Rejection> {
        let caps_ext = parts.extensions.get::<CapabilitySet>();
        let user = parts.extensions.get::<UserId>().copied();
        let tctx = parts.extensions.get::<TenantContext>().copied();
        let accept = parts.headers.get(header::ACCEPT)
            .and_then(|v| v.to_str().ok())
            .unwrap_or("");
        let wants_html = accept.contains("text/html") && !accept.contains("application/json");
        let path: Uri = parts.uri.clone();

        let Some(caps) = caps_ext else {
            // No JWT extension = no auth header processed.
            return Err(unauthenticated_response(wants_html, &path));
        };

        if !caps.contains(C::CAP) {
            tracing::warn!(
                tenant_id = tctx.map(|t| t.tenant_id.to_string()).unwrap_or_default(),
                user_id = user.map(|u| u.to_string()).unwrap_or_default(),
                required_cap = C::CAP.as_str(),
                path = %path,
                accept = %accept,
                "admin route capability denied",
            );
            return Err(forbidden_response(wants_html, C::CAP));
        }
        Ok(RequireCaps(PhantomData))
    }
}

fn unauthenticated_response(wants_html: bool, path: &Uri) -> Response {
    if wants_html {
        let next = urlencoding::encode(&path.to_string());
        Redirect::to(&format!("/admin/login?next={next}")).into_response()
    } else {
        AppError::Forbidden("missing_token".into()).into_response()
    }
}

fn forbidden_response(wants_html: bool, cap: Capability) -> Response {
    if wants_html {
        // Reusable HTML error page (P2).
        crate::admin::error_pages::forbidden(cap).into_response()
    } else {
        AppError::Forbidden(cap.as_str().to_owned()).into_response()
    }
}
```

//! Server-rendered HTML error pages for admin routes.

PERFORMANCE / SECURITY CONSIDERATIONS
═════════════════════════════════════════════════════════════════════

  - Extractor runs on EVERY admin request; keep it allocation-free.
    PhantomData carries zero runtime cost; the BTreeSet lookup is
    O(log n) where n ≤ 6 capabilities.
  - HTML error pages are server-rendered with inline styling — zero
    static-file dep, zero hydration. Acceptable size (~500 bytes).
  - Redirect path is URL-encoded via `url::form_urlencoded` —
    prevents open-redirect attacks via crafted `next` parameter
    when the login handler later honours it (W1 D4 / D5 covers).
  - The `tracing::warn!` on cap-fail logs `user_id` + `tenant_id` —
    review with ops to confirm log-storage retention policy aligns
    with GDPR (don't store more than necessary).
  - No PII (email / password) ever logged here.

═════════════════════════════════════════════════════════════════════
COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **Extractor order in handler signature.** `RequireCaps<C>` MUST
     come before `State<S>` and `Extension<T>` in the parameter list —
     axum runs extractors left-to-right. If `State` runs first and
     panics on missing AppState (it won't, but…), the cap-check is
     skipped.
  2. **`Accept: */*`** matches both text/html AND application/json
     globs. Our test uses contains-based sniffing; CLI tools usually
     send `*/*` — they'll get JSON, which is correct.
  3. **`urlencoding` crate not in workspace deps.** Use
     `url::form_urlencoded` (already in workspace) instead. Test that
     `/admin/posts?foo=bar` round-trips through the `next` param
     without double-encoding.
  4. **`xtask capability-coverage` regex update accidentally matches
     in test files.** Scope the file walker to `src/` only, not
     `tests/`. Existing implementation already does this — verify.
  5. **`require_caps!` macro hygiene.** Expanding inside `pub mod
     guard` exports the marker types via `pub use admin::guard::*;`
     — verify the export list in `admin/mod.rs` doesn't accidentally
     re-export the macro itself (it should NOT — `#[macro_export]` +
     `pub use` would double-export).
  6. **HTML in error_pages.rs** uses `format!` with `{}` placeholders
     — make sure to escape any user-controlled input (`required.as_str()`
     is a `&'static str` from the enum, safe). Future error pages
     accepting user data MUST go through `ammonia::clean` (M2 W8 D4).
