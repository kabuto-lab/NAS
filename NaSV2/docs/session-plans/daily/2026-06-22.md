P1 · `migrations/0002_sites_posts.sql` (NEW)

```sql
-- 0002_sites_posts.sql · expand-only · ENTITY §15, §17
--
-- Creates the two highest-traffic tenant-scoped tables: `sites` and
-- `posts`. RLS policies land in 0003 (this migration installs the
-- tables; 0003 enforces tenant isolation on top — split because
-- ALTER TABLE ENABLE RLS is a hard fence that breaks dev seed flows
-- if applied before any rows exist).
--
-- Tables:
--   - sites: 1 site = 1 logical CMS site within a tenant
--   - posts: posts/pages within a site
--
-- Indices:
--   - (tenant_id, slug) UNIQUE on sites
--   - (site_id, slug) UNIQUE on posts
--   - (status, published_at) on posts for list_published ordering

CREATE TABLE IF NOT EXISTS sites (
    id            UUID PRIMARY KEY,
    tenant_id     UUID NOT NULL,
    slug          TEXT NOT NULL,
    display_name  TEXT NOT NULL,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX IF NOT EXISTS sites_tenant_slug_idx
    ON sites (tenant_id, slug);

CREATE TABLE IF NOT EXISTS posts (
    id             UUID PRIMARY KEY,
    site_id        UUID NOT NULL REFERENCES sites(id) ON DELETE CASCADE,
    tenant_id      UUID NOT NULL,
    slug           TEXT NOT NULL,
    title          TEXT NOT NULL,
    status         TEXT NOT NULL
                   CHECK (status IN ('draft','scheduled','published','archived')),
    published_at   TIMESTAMPTZ,
    blocks         JSONB NOT NULL DEFAULT '[]'::jsonb,
    custom_type    TEXT,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE UNIQUE INDEX IF NOT EXISTS posts_site_slug_idx
    ON posts (site_id, slug);

CREATE INDEX IF NOT EXISTS posts_published_idx
    ON posts (site_id, status, published_at DESC);

CREATE INDEX IF NOT EXISTS posts_tenant_idx
    ON posts (tenant_id);

-- Trigger for updated_at automaticity.
CREATE OR REPLACE FUNCTION posts_set_updated_at() RETURNS trigger AS $$
BEGIN
    NEW.updated_at = now();
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER posts_set_updated_at_trg
    BEFORE UPDATE ON posts
    FOR EACH ROW EXECUTE FUNCTION posts_set_updated_at();
```

```rust
use clap::{Parser, Subcommand};
use eyre::Result;

#[derive(Parser)]
#[command(name = "nas2-cli", about = "AX•CMS dev/ops CLI")]
struct Cli {
    #[command(subcommand)]
    cmd: Cmd,
}

#[derive(Subcommand)]
enum Cmd {
    Db {
        #[command(subcommand)]
        sub: DbCmd,
    },
}

#[derive(Subcommand)]
enum DbCmd {
    /// Apply pending migrations via the admin_pool URL.
    Migrate,
}

#[tokio::main]
async fn main() -> Result<()> {
    let _ = dotenvy::dotenv();
    let cli = Cli::parse();
    match cli.cmd {
        Cmd::Db { sub: DbCmd::Migrate } => run_migrate().await,
    }
}

async fn run_migrate() -> Result<()> {
    let url = std::env::var("DATABASE_URL_ADMIN")
        .map_err(|_| eyre::eyre!("DATABASE_URL_ADMIN not set"))?;
    let pool = sqlx::postgres::PgPoolOptions::new()
        .max_connections(1)
        .acquire_timeout(std::time::Duration::from_secs(5))
        .connect(&url).await?;
    sqlx::migrate::Migrator::new(std::path::Path::new("migrations"))
        .await?
        .run(&pool).await?;
    println!("migrations applied");
    Ok(())
}
```

COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **`sqlx::migrate::Migrator::new(path).await?`** — async because
     it reads the directory. Don't try to use the `sqlx::migrate!`
     macro (compile-time path resolution + DATABASE_URL requirement).
  2. **`status TEXT NOT NULL CHECK (...)` vs `CREATE TYPE`.** Domain
     uses `PostStatus` enum; SQL could use `CREATE TYPE post_status
     AS ENUM (...)`. `CHECK` is simpler — no migration churn when
     adding a status. `CREATE TYPE` is faster on huge tables. Pick
     CHECK now; revisit if pg_stat shows CHECK overhead.
  3. **`ON DELETE CASCADE`** on `posts.site_id` — when a site is
     deleted, posts go too. Verify this is desired (it is — sites
     are user-managed, deletion implies content removal).
  4. **`tenant_id` redundancy on posts.** posts.tenant_id duplicates
     sites.tenant_id. Necessary: RLS policies need tenant_id directly
     on each table for the policy USING clause (next migration). Cost:
     8 bytes/row. Worth it.
  5. **Timestamp default `now()` vs `clock_timestamp()`** — `now()`
     is transaction-start timestamp. Posts within a single import
     batch will share it. Acceptable; switch to `clock_timestamp()`
     if log correlation needs sub-tx resolution.
