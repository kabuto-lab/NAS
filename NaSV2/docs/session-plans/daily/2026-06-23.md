```markdown
# ADR-010 — RLS policy shape for tenant-scoped tables

## Context
ENTITY §3.3 + §15 mandate RLS for every tenant-scoped table. The
shape MUST be uniform so that:
  - reviewers can mechanically verify a new migration follows the
    pattern
  - `xtask architecture-check` can grep for non-conforming policies
    (future enhancement — month 2+)
  - the `set_config('app.tenant_id', $1, true)` contract (§3.5) is
    the SINGLE knob that gates all access

## Decision

For every tenant-scoped table `T` with column `tenant_id UUID NOT
NULL`, the migration creating policies on `T` MUST:

1. **Enable + force RLS:**
   ```sql
   ALTER TABLE t ENABLE ROW LEVEL SECURITY;
   ALTER TABLE t FORCE ROW LEVEL SECURITY;
   ```
   `FORCE` makes RLS apply even to the table owner — defence against
   accidental DDL-role queries.

2. **Single tenant-isolation policy named `<table>_tenant_isolation`:**
   ```sql
   CREATE POLICY t_tenant_isolation
       ON t
       USING (tenant_id = current_setting('app.tenant_id')::uuid)
       WITH CHECK (tenant_id = current_setting('app.tenant_id')::uuid);
   ```
   Both USING (for reads) and WITH CHECK (for inserts/updates).

3. **No additional policies** for the same table in this migration —
   layered policies (e.g. row-level capability filtering) belong to a
   later migration so the basic isolation invariant is provable in
   isolation.

4. **Grant** to a dedicated `ax_app` role:
   ```sql
   GRANT SELECT, INSERT, UPDATE, DELETE ON t TO ax_app;
   ```
   The HTTP / worker pools connect as `ax_app`, not as superuser.
   `ax_app` is created by `0002` via `CREATE ROLE` — or by ops if
   already present (`DO $$ BEGIN ... EXCEPTION ...`).

## Failure modes prevented

- Missing `current_setting('app.tenant_id')` → policy returns no
  rows → fail-closed (rather than returning all rows).
- `current_setting` with `true` (missing_ok) parameter on the
  *write* side would silently allow `tenant_id=NULL` inserts to
  bypass — DO NOT use missing_ok; default-strict.
- Bypassing via `SECURITY DEFINER` functions: forbidden in our
  schema. Any future migration introducing such a function needs an
  explicit ADR.

## TLA layers

- L1: policy uniformity = provable isolation invariant per table.
- L2: single `set_config` per request = one extra `SELECT` per
  transaction (~30 µs). Acceptable; §3.5 budget.
- L3: policies scale with tenant_id index — already present.
- L4: drift detection — proptest in VAL-005 catches if a future
  migration forgets a policy.

## References
- RFC-005 (CSRF) — separately ensures app-level checks at write
  boundary
- VAL-005 (RLS isolation proptest) — verification
```

#[tokio::test]
#[ignore = "needs Docker"]
async fn posts_status_check_constraint_enforced() {
    let (_pg, pool) = boot_pg_and_migrate().await;
    // Seed a site first
    let site_id = uuid::Uuid::new_v4();
    let tenant_id = uuid::Uuid::new_v4();
    sqlx::query(
        "INSERT INTO sites (id, tenant_id, slug, display_name) \
         VALUES ($1, $2, 'demo', 'Demo')"
    ).bind(site_id).bind(tenant_id).execute(&pool).await.unwrap();

    // Insert with invalid status — must fail
    let post_id = uuid::Uuid::new_v4();
    let res = sqlx::query(
        "INSERT INTO posts (id, site_id, tenant_id, slug, title, status, blocks) \
         VALUES ($1, $2, $3, 'hi', 'Hi', 'wat', '[]'::jsonb)"
    ).bind(post_id).bind(site_id).bind(tenant_id).execute(&pool).await;
    assert!(res.is_err(), "invalid status must be rejected by CHECK");
}

#[tokio::test]
#[ignore = "needs Docker"]
async fn posts_updated_at_trigger_bumps() {
    let (_pg, pool) = boot_pg_and_migrate().await;
    let site_id = uuid::Uuid::new_v4();
    let tenant_id = uuid::Uuid::new_v4();
    let post_id = uuid::Uuid::new_v4();
    sqlx::query("INSERT INTO sites (id, tenant_id, slug, display_name) \
                 VALUES ($1, $2, 'demo', 'Demo')")
        .bind(site_id).bind(tenant_id).execute(&pool).await.unwrap();
    sqlx::query(
        "INSERT INTO posts (id, site_id, tenant_id, slug, title, status, blocks) \
         VALUES ($1, $2, $3, 'hello', 'Hello', 'draft', '[]'::jsonb)"
    ).bind(post_id).bind(site_id).bind(tenant_id).execute(&pool).await.unwrap();

    let (initial,): (chrono::DateTime<chrono::Utc>,) = sqlx::query_as(
        "SELECT updated_at FROM posts WHERE id=$1"
    ).bind(post_id).fetch_one(&pool).await.unwrap();

    tokio::time::sleep(std::time::Duration::from_millis(10)).await;

    sqlx::query("UPDATE posts SET title='World' WHERE id=$1")
        .bind(post_id).execute(&pool).await.unwrap();

    let (after,): (chrono::DateTime<chrono::Utc>,) = sqlx::query_as(
        "SELECT updated_at FROM posts WHERE id=$1"
    ).bind(post_id).fetch_one(&pool).await.unwrap();

    assert!(after > initial, "updated_at trigger must bump on UPDATE");
}

COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **`testcontainers` Postgres image lacks pgmq extension.** Don't
     apply 0001 in these tests — read 0002 SQL directly. Production
     migration order is unchanged.
  2. **`current_setting('app.tenant_id')` raises if unset and missing_ok=false.**
     That's the *intended* behaviour — fail-closed. Tests demonstrating
     "no GUC = no rows" use `current_setting(..., true)` only in test
     diagnostics, NEVER in policies.
  3. **`ALTER TABLE FORCE ROW LEVEL SECURITY`** applies to table owners
     too. In our case `ax_app` is the app role, postgres superuser is
     `postgres` (migrations). Migrations work fine — superuser bypasses
     unless FORCE. With FORCE, migrations connect through admin_pool
     which uses superuser-ish credentials anyway; document.
  4. **GRANT order**. GRANT before policies = role can see all rows
     temporarily. Convention: enable RLS BEFORE GRANT, so the role
     never has unfiltered visibility.
  5. **CREATE ROLE idempotency**. `IF NOT EXISTS` doesn't apply to
     CREATE ROLE; use the `DO $$` block.
