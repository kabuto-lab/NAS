# ROLLBACK-0003 — RLS on sites + posts

## Reverse direction (disaster recovery only)
```sql
DROP POLICY IF EXISTS posts_tenant_isolation ON posts;
DROP POLICY IF EXISTS sites_tenant_isolation ON sites;
ALTER TABLE posts NO FORCE ROW LEVEL SECURITY;
ALTER TABLE posts DISABLE ROW LEVEL SECURITY;
ALTER TABLE sites NO FORCE ROW LEVEL SECURITY;
ALTER TABLE sites DISABLE ROW LEVEL SECURITY;
REVOKE ALL ON posts FROM ax_app;
REVOKE ALL ON sites FROM ax_app;
```

schema reset (with subsequent re-application) or full disaster

#[tokio::test]
#[ignore = "needs Docker"]
async fn rls_blocks_cross_tenant_read() {
    let (_pg, pool) = boot_pg_and_migrate().await;

    // Apply 0003 manually since boot_pg_and_migrate only applied 0002.
    let sql_0003 = std::fs::read_to_string("../../migrations/0003_rls_sites_posts.sql")
        .expect("read 0003");
    sqlx::query(&sql_0003).execute(&pool).await.expect("apply 0003");

    let tenant_a = uuid::Uuid::new_v4();
    let tenant_b = uuid::Uuid::new_v4();
    let site_a = uuid::Uuid::new_v4();

    // Open a connection as `ax_app` for the assertions.
    // Strategy: switch role inline via `SET LOCAL ROLE` for tests
    // (production uses dedicated ax_app credentials).
    let mut tx = pool.begin().await.unwrap();
    sqlx::query("SET LOCAL ROLE ax_app").execute(&mut *tx).await.unwrap();

    // Tenant A inserts a site + post. Must set app.tenant_id first.
    sqlx::query("SELECT set_config('app.tenant_id', $1, true)")
        .bind(tenant_a.to_string()).execute(&mut *tx).await.unwrap();

    sqlx::query(
        "INSERT INTO sites (id, tenant_id, slug, display_name) \
         VALUES ($1, $2, 'a', 'A')"
    ).bind(site_a).bind(tenant_a).execute(&mut *tx).await.unwrap();

    sqlx::query(
        "INSERT INTO posts (id, site_id, tenant_id, slug, title, status, blocks) \
         VALUES ($1, $2, $3, 'hi', 'Hi', 'published', '[]'::jsonb)"
    ).bind(uuid::Uuid::new_v4()).bind(site_a).bind(tenant_a)
     .execute(&mut *tx).await.unwrap();

    tx.commit().await.unwrap();

    // Now switch to tenant B's view — same pool, NEW transaction.
    let mut tx2 = pool.begin().await.unwrap();
    sqlx::query("SET LOCAL ROLE ax_app").execute(&mut *tx2).await.unwrap();
    sqlx::query("SELECT set_config('app.tenant_id', $1, true)")
        .bind(tenant_b.to_string()).execute(&mut *tx2).await.unwrap();

    let (count,): (i64,) = sqlx::query_as("SELECT count(*)::bigint FROM posts")
        .fetch_one(&mut *tx2).await.unwrap();
    assert_eq!(count, 0, "tenant B must see ZERO of tenant A's posts");

    let (sites_count,): (i64,) = sqlx::query_as("SELECT count(*)::bigint FROM sites")
        .fetch_one(&mut *tx2).await.unwrap();
    assert_eq!(sites_count, 0, "tenant B must see ZERO of tenant A's sites");
}

COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **`SET LOCAL ROLE` requires the role to exist.** 0003 creates
     ax_app idempotently — verify the test runs 0003 after 0002.
  2. **`SET LOCAL ROLE` resets at COMMIT.** Each test uses fresh
     transactions, which is the production pattern (transaction-scoped
     tenant context — ENTITY §3.5).
  3. **`current_setting('app.tenant_id')::uuid`** errors if cast
     fails. The set_config call with `true` (transaction-scoped)
     should always set it before any SELECT/INSERT; if it doesn't, the
     test will surface that error rather than a silent leak.
  4. **`sqlx::query("SELECT set_config(...)")::execute`** vs
     `fetch_one` — `set_config` returns a value; using `execute`
     ignores it, which is what we want.
  5. **pgbouncer transaction mode in production** rebinds backend
     connections at every transaction. The GUC must be set inside
     the SAME transaction as the business statement — ENTITY §3.5
     is the law. Tests demonstrate this; production code (W6) makes
     it the pattern.
