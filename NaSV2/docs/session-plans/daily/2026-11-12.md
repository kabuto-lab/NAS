```rust
async fn issue_refresh(&self, prev: &JwtClaims, ttl_secs: i64)
    -> Result<(String, JwtClaims), AppError>
{
    let now = chrono::Utc::now().timestamp();
    let new_claims = JwtClaims {
        sub: prev.sub,
        tenant: prev.tenant,
        caps: prev.caps.clone(),
        iat: now,
        exp: now + ttl_secs,
        jti: uuid::Uuid::new_v4(),
        iss: prev.iss.clone(),
    };
    let token = self.issue(new_claims.clone()).await?;
    Ok((token, new_claims))
}
```

  Edit `crates/presentation/src/auth/jwt_middleware.rs` from M2 W7 D2.
  After successful verification + jti-cache check, compute:

```rust
const REFRESH_WINDOW_PCT: f64 = 0.75;  // last 25% of lifetime
const DEFAULT_TTL_SECS: i64 = 3600;

// in jwt_middleware after `state.jti_cache.insert(claims.jti, ()).await;`:

let now = chrono::Utc::now().timestamp();
let life = claims.exp - claims.iat;
let elapsed = now - claims.iat;
let refresh_threshold = (life as f64 * REFRESH_WINDOW_PCT) as i64;
let mut refreshed_cookie: Option<String> = None;

if life > 0 && elapsed >= refresh_threshold {
    if let Some(issuer) = state.issuer.as_ref() {
        if let Ok((new_token, _new_claims)) =
            issuer.issue_refresh(&claims, DEFAULT_TTL_SECS).await
        {
            let cookie = format!(
                "ax_session={new_token}; HttpOnly; Secure; SameSite=Strict; \
                 Path=/; Max-Age={DEFAULT_TTL_SECS}"
            );
            refreshed_cookie = Some(cookie);
            tracing::info!(jti_old = %claims.jti, "jwt sliding-refresh");
        }
    }
}

// Inject CapabilitySet/UserId/claims as before (unchanged).
req.extensions_mut().insert(set);
req.extensions_mut().insert(claims.sub);
req.extensions_mut().insert(claims);

let mut response = next.run(req).await;
if let Some(cookie) = refreshed_cookie {
    if let Ok(v) = axum::http::HeaderValue::from_str(&cookie) {
        response.headers_mut().insert(axum::http::header::SET_COOKIE, v);
    }
}
Ok(response)
```

P3 · `crates/presentation/src/admin/logout.rs` (NEW)

```rust
//! POST /admin/logout — clears cookies + denylists current jti.

use axum::{
    extract::{Extension, State},
    http::{header, HeaderMap, HeaderValue, StatusCode},
    response::{IntoResponse, Redirect, Response},
};
use nas2_application::auth::jwt::JwtClaims;

use crate::app_state::AppState;
use crate::auth::jwt_middleware::JwtMiddlewareState;

// no_capability_required: logout is universal
pub async fn logout(
    State(jwt_state): State<JwtMiddlewareState>,
    Extension(claims): Extension<JwtClaims>,
) -> Response {
    // Denylist for the remaining lifetime — prevents reuse if the
    // cookie somehow leaks before expiry.
    let now = chrono::Utc::now().timestamp();
    let remaining = (claims.exp - now).max(0) as u64;
    if remaining > 0 {
        // moka Cache with global TTL — per-key TTL via insert_with_ttl
        // would be cleaner, but moka 0.12 doesn't expose per-key TTL
        // directly. Acceptable: the denylist cache's global TTL is
        // set to DEFAULT_TTL_SECS at construction.
        jwt_state.jti_denylist.insert(claims.jti, ()).await;
        tracing::info!(jti = %claims.jti, "logout — jti denylisted");
    }

    let mut headers = HeaderMap::new();
    for cookie in [
        "ax_session=; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=0",
        "ax_csrf=; Secure; SameSite=Strict; Path=/; Max-Age=0",
    ] {
        if let Ok(v) = HeaderValue::from_str(cookie) {
            headers.append(header::SET_COOKIE, v);
        }
    }

    (StatusCode::SEE_OTHER, headers, Redirect::to("/admin/login?logged_out=1"))
        .into_response()
}
```

═════════════════════════════════════════════════════════════════════
PERFORMANCE / SECURITY CONSIDERATIONS
═════════════════════════════════════════════════════════════════════

  - Refresh runs on EVERY request inside the window — for a chatty
    UI (~10 req/min), that's a fresh token every 25 min. Acceptable;
    the issue+sign cost is ~10 µs (HS256).
  - jti denylist Cache: 100k capacity, TTL = max token lifetime
    (3600s). Memory: ~16 bytes/entry × 100k = ~1.5 MB. Fine.
  - Refresh-cookie path requires the response is a single Response
    object (not a stream) — for SSE/WebSocket the refresh is
    skipped silently. Document.
  - Logout deliberately doesn't return 401 — that would trigger
    browser auth prompt. 303 SEE_OTHER + redirect is the right
    semantic.
  - No token in URL params (logout via cookie). The form-based
    POST + CSRF token guarantees same-origin.

═════════════════════════════════════════════════════════════════════
COMMON PITFALLS
═════════════════════════════════════════════════════════════════════

  1. **Refresh window calculation overflow** — `life * 0.75 as i64`
     for life=3600 = 2700 — safe. For long-lived tokens (e.g. CI
     bots with 30-day life), still safe (well under i64::MAX).
  2. **issue_refresh during DB transaction** — issuer doesn't touch
     DB. No risk.
  3. **Set-Cookie race condition** — if a client makes 2 concurrent
     requests both in refresh window, both get fresh tokens. Last
     write wins on the client. Acceptable; jti_cache treats each as
     a distinct first-use.
  4. **denylist TTL** — moka 0.12 supports per-entry TTL via
     `expire_after`. Use a builder with `Expiry` impl to make each
     entry expire at its token's exp time. Fallback: global TTL =
     DEFAULT_TTL_SECS (acceptable; entries linger a bit longer).
  5. **Logout without token** — if `Extension<JwtClaims>` is missing,
     axum returns 500. Wrap in `Option<Extension<JwtClaims>>` and
     handle gracefully (or rely on RequireCaps-like extractor).
