  first run** despite Windows-host noise; baseline.json captured
  4 samples from `pool_mode_from_str`.

### Bad

- **Pre-existing `cargo fmt --check` drift across ~25 tracked
  files** (domain, application, presentation, common — files
  *touched in prior commits but never run through rustfmt*). No
  pre-commit hook enforces fmt, so the drift accumulated. Fix is
  one `cargo fmt --all` + one commit; logged as next-month
  proposal (§7-3 below). NOT fixed this month — out of W4 D2..D5
  scope per the daily prompts.
- **`xtask check-planning-refs --commit HEAD` interprets the arg
  as a `git log` range_spec, not a single SHA.** So bare `HEAD`
  walks 73 commits and trips on 20 historical bootstrap commits
  that never referenced RFC/ADR/PLAN/VAL. Workaround: pass
  `HEAD~1..HEAD` or use the gate in CI for new commits only.
  Logged as next-month proposal (§7-5).
- **The git repo root is `barbie/AX/`, not `NaSV2/`.** Discovered
  during W4 D2 staging. Means `git add` paths must include
  `NaSV2/` prefix when run from inside the parent repo. Not a
  problem per se, but a noted topology fact for future sessions.
