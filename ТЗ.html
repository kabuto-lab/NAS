Four-Layer architecture · TLA Entity

AX следует строгой 4-слойной декомпозиции (ENTITY.md §2) с compile-time enforcement через Cargo workspace dependencies и cargo xtask architecture-check. Поток зависимостей однонаправленный: Presentation → Application → Domain ← Infrastructure (адаптер pattern).

L1 · Presentation

crates/presentation
Adapters — Axum API surface, Leptos SSR (Phase B), middleware (tenant_resolver, request_id, error_to_response), OpenAPI generator (utoipa). НЕ содержит бизнес-логики, только маршрутизацию + serialization + rendering.
Depends on: application · common

L2 · Application

crates/application
Use cases (GetPublishedBySlug), port traits (CmsRepository, CmsRenderer), cross-cutting services (audit, notifications). Тонкие use cases — делегируют в repo. Здесь живёт бизнес-policy («только published»), не domain-логика.
Depends on: domain · common · NO: sqlx, axum, tokio

L3 · Domain

crates/domain
Pure aggregates (PublishedPage), value objects (PageSlug, PageLocale, Block enum), invariants. ZERO external deps кроме serde, uuid, chrono, garde. Не знает о DB, HTTP, async.
Depends on: common (base types only) · NO: tokio, sqlx, axum, reqwest, sentry, tracing

L4 · Infrastructure

crates/infrastructure
Adapter implementations: SQLx repos, S3 client, pgmq client, email (lettre). with_tenant(pool, ctx, |tx|) — единственный entry-point в БД. Row → aggregate mapping ВНУТРИ слоя (sqlx::Row не утекает наружу).
Depends on: application (implements traits) · domain · common

Поток зависимостей (схема)

┌──────────────────────────────────────────────────────────────┐ │ L1 Presentation (Axum router, Leptos SSR, middleware) │ └──────────┬───────────────────────────────────────────────────┘ │ uses ports (trait CmsRepository, …) ▼ ┌──────────────────────────────────────────────────────────────┐ │ L2 Application (use cases, port traits) │ └──────────┬─────────────────────────────────────────▲─────────┘ │ owns domain types │ implements ports ▼ │ ┌──────────────────────────────┐ ┌────────────────┴─────────┐ │ L3 Domain (pure types) │ │ L4 Infrastructure │ │ PublishedPage, Block, │◄───┤ PgCmsRepository, │ │ PageSlug, PageLocale, … │ │ with_tenant, PgPool │ └──────────────────────────────┘ └───────────────────────────┘ Circular imports impossible: Cargo workspace deps структурно отрицают. Boundary enforcement: cargo xtask architecture-check (CI gate).

Multi-tenancy — 5 levels of defense

Расширение SITE1 4-слойной защиты (bridge/02 §1) +1 compile-time уровень — newtype TenantId(Uuid) делает «забыли скоупнуть» невозможным на этапе типизации.

#УровеньТехнологияFailure mode
1DNS / reverse-proxyCaddy 2 on-demand TLS, slug-based subdomain routingWrong tenant сайт даже не доходит до AX
2Axum middlewaretenant_resolver: Host → TenantId через moka LRU (5 min TTL)Unknown slug → 404 без вызова handler'а
3Request contextExtension<TenantContext> + TenantId(Uuid) newtypeHandler не может accidentally подставить UserId — компилятор отрежет
4Postgres RLSSET LOCAL app.current_tenant_id = $1 в transaction + POLICY rls_cms_pages_tenant_isolationДаже если SQL забыл WHERE tenant_id — RLS отрезает чужие row'ы
5DB schematenant_id NOT NULL + composite indexes начинаются с tenant_id + partial uniqueCross-tenant writes physically impossible
Critical caveat (ENTITY.md §3): RLS с SET LOCAL требует PgBouncer в transaction pool mode. В session mode SET LOCAL держится между запросами и пул сжирается; в statement mode SET LOCAL вообще не работает. Без правильного PgBouncer — вся защита разваливается.

Schema delta — expand-only migration

-- migrations/0001_cms_pages_expand.sql

CREATE OR REPLACE VIEW cms_pages_v_active AS
SELECT id, tenant_id, slug, locale, title, body, status,
       meta_title, meta_description, cover_image_key,
       published_at, created_at, updated_at
FROM cms_pages
WHERE status = 'published';

ALTER TABLE cms_pages ENABLE ROW LEVEL SECURITY;

CREATE POLICY rls_cms_pages_tenant_isolation
  ON cms_pages
  USING (tenant_id = current_setting('app.current_tenant_id', true)::uuid);

CREATE ROLE site1_admin_role NOLOGIN;
GRANT ALL ON cms_pages TO site1_admin_role;
ALTER ROLE site1_admin_role BYPASSRLS;

CREATE ROLE ax_app_role NOLOGIN;
GRANT SELECT ON cms_pages_v_active TO ax_app_role;
GRANT SELECT ON cms_pages TO ax_app_role;
